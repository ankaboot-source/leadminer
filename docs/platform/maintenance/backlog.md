# Documentation backlog

> Prioritized list of documentation work and documentation-adjacent fixes for the Leadminer platform. Read this before starting a documentation task to see what is already recorded and why it matters.

## TL;DR

- P0 covers a security finding: credential-shaped values are committed in `leadminer.io/supabase/functions/.env.*`. Rotate and purge them outside the documentation work.
- P1 covers the largest documentation-quality wins: shorten and split the root `AGENTS.md`, add a CI documentation check, enable the upstream `backup` role, and move the Supabase overrides out of `sed`/heredoc mutations.
- P2 covers discoverability and accuracy fixes: move the docs to a dedicated repository when edit access demands it, fix stale links, correct README claims, and add missing root files.
- Every item names the evidence and the action. Items that depend on human approval are marked.

## Backlog details for the required P1 items

### BL-02: root `AGENTS.md` reduction

- Target: under 200 lines.
- Precedent: `wikiadviser/AGENTS.md` (147 lines). It opens with "Every line is sourced from a config file or a past session correction — no generic advice" at line 3.
- Required new files:
  - `CLAUDE.md` with `@AGENTS.md` as its first line.
  - Nested `AGENTS.md` in `backend/`, `frontend/`, `micro-services/emails-fetcher/`, and `supabase/functions/`.
- Do not duplicate the `docs/` tree in `AGENTS.md`. Link to it instead.

### BL-03: `docs-check.yml`

The job should run on `push` and `pull_request` for paths under `docs/**` and for the root `AGENTS.md` and `README.md`.

- `markdownlint-cli2` for structure.
- `lychee` for link rot.
- The stale-reference check in `doc-health-audit.md` for workflow names and file paths.

## Known gaps

- Whether `email-signature-extractor` has a live consumer outside the repositories examined is not documented. The README is a single line.
- The credential rotation and git-history purge for BL-01 require human approval and a security review. They are not documentation tasks.
- The `leadminer.io/docs/DEPLOY.md` replacement content depends on the final workflow set. The file must be regenerated from `leadminer.io/.github/workflows/` after the workflow set stabilizes.
