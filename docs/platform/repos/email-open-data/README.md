# Email Open Data

> The email domain and banned-IP data source for Leadminer. Read this if you need to know which list a domain belongs to, how the lists are refreshed, or which Leadminer components consume them.

## TL;DR

- This repository publishes free, disposable, public, ISP, and banned-IP lists (`README.md:7-14`).
- The lists are generated by one GitHub Actions workflow, `fetch-new-data.yaml`.
- The workflow is scheduled daily at midnight (`fetch-new-data.yaml:3-4`).
- Leadminer consumes the disposable and public lists in `backend/src/fetchProviders.ts:10,13`.
- The ops repository consumes the banned-IP list in `blacklist-checker.sh:11`.

## Data files

The repository publishes JSON and TXT versions of each list:

| List       | Files                                                           | Meaning                                                           |
| ---------- | --------------------------------------------------------------- | ----------------------------------------------------------------- |
| Free       | `free-email-domains.json`, `free-email-domains.txt`             | Free email providers such as `gmail.com` (`README.md:8`).         |
| Disposable | `disposable-email-domains.json`, `disposable-email-domains.txt` | Disposable email providers such as `yopmail.com` (`README.md:9`). |
| Public     | `public-email-providers.json`, `public-email-providers.txt`     | Public email providers such as `pm.me` (`README.md:10`).          |
| ISP        | `ISP-domains.json`, `ISP-domains.txt`                           | ISP providers, also included in free (`README.md:11`).            |
| Banned IPs | `mailserver-banned-ips.json`, `mailserver-banned-ips.txt`       | Banned mail server IP addresses (`README.md:12`).                 |

A domain belongs to only one list, except ISP (`README.md:14`).

## Refresh workflow

The workflow `.github/workflows/fetch-new-data.yaml` downloads source lists with `curl` and `wget`, merges them, and commits the updated files (`fetch-new-data.yaml:13-73`).

- It runs on a schedule (`fetch-new-data.yaml:3-4`).
- It downloads disposable domains from `disposable/disposable-email-domains` (`fetch-new-data.yaml:18`).
- It downloads free providers from `Kikobeats/free-email-domains` and a gist (`fetch-new-data.yaml:22-25`).
- It downloads ISP domains from `Immortalin/email-domain-db` (`fetch-new-data.yaml:30-36`).
- It downloads banned IPs from Spamhaus and Stop Forum Spam (`fetch-new-data.yaml:47-53`).
- It regenerates the JSON files with `jq` (`fetch-new-data.yaml:57-60`).
- It commits the updated files with `git commit` and `git push` (`fetch-new-data.yaml:72-73`).

The README states that the files are updated hourly (`README.md:16`). The workflow schedule is daily at midnight (`fetch-new-data.yaml:4`). The two sources disagree.

## Consumers

### Leadminer backend

The backend downloads the disposable and public lists from the repository's raw GitHub URLs (`backend/src/fetchProviders.ts:10,13`). It saves them to local JSON files (`backend/src/fetchProviders.ts:6-17`).

### Leadminer ops

The ops repository's `blacklist-checker.sh` reads the banned-IP list from the repository's raw URL (`leadminer.io/blacklist-checker.sh:11`). The script checks whether an IP appears in the list (`blacklist-checker.sh:16`).

## Known gaps

- The README says the files are updated hourly (`README.md:16`); the workflow runs daily at midnight (`fetch-new-data.yaml:4`). One of the two is wrong.
- The repository has no `AGENTS.md`.
- The workflow depends on third-party URLs. If a source changes its path or format, the workflow fails on the next run.
